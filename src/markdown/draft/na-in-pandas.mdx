### Compatibility with NumPy

- NumPy data types

NumPy has five basic numerical types: `bool`, `int`, `uint`, `float`, and `complex`. A basic numerical type name combined with a numeric bitsize defines a concrete type, e.g. `numpy.float64` is a 64-bit floating point data type.

In addition to numerical types, NumPy supports storing unicode strings (`numpy.str_`), null-terminated byte sequences (`numpy.bytes_`), and arbitrary byte sequences (`numpy.void`). They are parameterized by a fixed width in either bytes or unicode points. `numpy.dtypes.StringDType` is a relatively recent addition for flexible user-defined data types, which supports variable-width string data.

Starting from NumPy 1.7, `datetime64` is natively supported as a core array data type, and `timeselta64` was created to complement `datetime64`. But NumPy does not support timezone-aware datetimes as of Oct 2024.


- How does NumPy handle missing values?

| Type | Null | NaN | Notes |
| ---- | ---- | --- | ----- |
| `bool` | string |   |   |
| `int` | string |   |   |
| `uint` | string |   |    |
| `float` | string |   |    |
| `complex` | string |   |   |
| `datetime64` | string |  NaT (not a time) |   |
| `timedelta64` | string | NaT (not a time) |  Created to complement `datetime64`. |
| `str_` |     |       |      |
| `bytes_` |     |       |      |
| `void` |     |       |      |
| `StringDType` | '' (empty string) | | Optionally, you can pass `na_object` as a keyword argument for the initializer. |

> **Note:** The na_object can be any arbitrary python object. Common choices are `numpy.nan`, `float('nan')`, `None`, an object specifically intended to represent missing data like `pandas.NA`, or a (hopefully) unique string like `"__placeholder__"`.

NaN-like sentinels and string sentinels, which includes the python `nan` float, the pandas missing data sentinel `pd.NA`, [returns itself in arithmetic operations, and sorts to the end of an array](https://numpy.org/devdocs/user/basics.strings.html#nan-like-missing-data-sentinels).

String missing data values are inatances / subtypes of `str`. They are treated as if they have a value given by the string sentinel.

Other sentinels, such as `None` raises an error in string operations.

- How are pandas data types different from NumPy?

> pandas defines an interface for implementing data types and arrays that extend NumPy’s type system. pandas itself uses the extension system for some types that aren’t built into NumPy (categorical, period, interval, datetime with timezone).

The interface consists of two classes: `pandas.api.extensions.ExtensionDtype` and `pandas.api.extensions.ExtensionArray`.
